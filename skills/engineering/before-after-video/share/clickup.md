# Post to a ClickUp task comment

The ClickUp MCP cannot attach a file to a comment (`mcp__clickup__clickup_request_attachment_upload` attaches to the task), so post through the web UI with Claude in Chrome. ClickUp's composer often ignores the extension's synthetic clicks and typing; drive it with page JavaScript (`mcp__claude-in-chrome__javascript_tool`). The selectors below are as of 2026-10; if one matches nothing, inspect the composer with `mcp__claude-in-chrome__read_page` and adapt.

1. Open the task URL in a new tab (`mcp__claude-in-chrome__navigate`); wait ~5 s.
2. Click into the comment box, then type the caption first: focus `.comment-bar__editor [contenteditable=true]` and `document.execCommand('insertText', false, text)`. Keep it ASCII-friendly. ⚠️ Text goes in BEFORE the video: an `insertText` into a draft that already holds a video wiped the whole draft, and the upload stayed behind only as a task attachment (2026-10-12).
3. Open the comment's attach menu: `document.querySelector('.comment-bar-root .cu-cloud-buttons-dropdown__toggle').click()`. Wait ~1.5 s, then tag the input inside the overlay: `[...document.querySelectorAll('input[type=file]')].filter(i => i.closest('.cdk-overlay-container')).forEach(i => i.setAttribute('aria-label', 'COMMENT_OVERLAY_FILE_INPUT'))`. `find` that exact label and `mcp__claude-in-chrome__file_upload` the MP4 paths to its ref (under 10 MB per call). ⚠️ An untagged `find` can return the TASK's attachment input, and the video then lands in task attachments, not the comment. Upload the `~/Downloads` copies from the Deliver step: the upload tool only accepts files from folders shared with the session, so paths under OUT may be refused.
4. Wait ~6 s, then confirm the draft: `.comment-bar__editor [contenteditable=true]` holds one `video` per file AND still contains your text, and `.comment-bar-root` innerHTML contains each file name.
5. `document.querySelector('.comment-bar__send').click()`.
6. Make the window tall first (`mcp__claude-in-chrome__resize_window` to about 1600×1000): in a short window (~570 px) the Activity panel draws only the history rows, not the comments, so the next check returns `[]` even when the post worked (2026-10-13). Then check it in the page: `[...document.querySelectorAll('video')].map(v => v.currentSrc || v.src)` must list one URL per file, ending in each file name, and `mcp__clickup__clickup_get_task_comments` must return the comment with your text (its `comment_text` holds the text only, not the video URLs). Done when both checks pass. If an earlier comment points at older files, update it with `mcp__clickup__clickup_update_comment` (text-only comments are safe to rewrite this way).

**Fallback** when the composer cannot be driven: upload each MP4 as a task attachment with `mcp__clickup__clickup_request_attachment_upload`, then post a comment with `mcp__clickup__clickup_create_comment` that names the files. Tell the user the videos sit in the task's attachments, not inside the comment.

Deleting old comments or attachments is permanent: leave it to the user and tell them which ones.
